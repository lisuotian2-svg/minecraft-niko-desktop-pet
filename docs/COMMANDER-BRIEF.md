## 2. 桌宠产品的质量门槛

| 维度 | 可观察门槛 |
|---|---|
| 视觉质感 | 保持 Minecraft 方块、像素贴图和 Slim 双层结构；80、220、500 px 及 100%、125%、150% DPI 下轮廓清晰，无 UV 错位、黑/白矩形边、肢体裁切或糊纹理。光照、火焰和粒子服务角色，不铺暗桌面；桌宠窗永远无文字、气泡、名牌。 |
| 动画密度 | 待机持续有呼吸、3–7 s 眨眼、低频环顾；走/转/伸展/坐/睡/醒/吃/摸头/拖拽/探头各有可辨认姿态。动作切换约 150–300 ms 从当前姿态插值；脚贴任务栏，不能瞬移、穿肢或长时间冻结。显著日常动作默认约每 2–5 分钟一次，提供密度设置。 |
| 行为智能 | 系统空闲、全屏、亮度、用户操作和声音偏好共同决定行为；拖拽/拍照/关闭能安全打断，完成后回到合理状态。手动火把优先于自动；正在吃/睡/探头时不叠加冲突动作。默认低打扰、可关闭随机互动，不建立饥饿/心情数值。 |
| 系统集成 | 透明区域点击穿透且桌宠不抢焦点；托盘单击找回、右键菜单、单实例、全局快捷键、登录自启、显示器/DPI 热变、全屏探头、拍照均能在 Windows 11 实机运行。设置即时生效、重启保持；WMI 不支持时清楚显示状态，手动火把仍可用。 |
| 稳定与性能 | `pnpm build`、`pnpm test`、strict `tsc` 全绿；PRD 的待机 CPU <3%、走路 <8% 作为本机测量门槛，隐藏时渲染趋近 0；2 小时含动作/显隐/拍照的运行中内存无持续单向增长。异常不丢设置/照片，IPC 失败留日志并恢复可操作状态。 |
| 包装交付 | 便携 exe、NSIS 安装包、源码 zip 均能在离线、干净目录使用；打包后皮肤/音频/粒子/托盘图标/截图可用。安装与卸载保留用户数据；便携版移动路径后的自启行为有明确处理；产物不上传、不公开分发。 |
| 用户体验 | 首启向导可跳过并有尺寸实时预览；设置页原生 TS/CSS，按“通用/交互/环境/拍照/关于”组织，显示亮度与快捷键冲突原因；静音和音量可立即验证。默认安静、不弹营销或调试信息；设置窗口是唯一正常文字入口。 |

阻断项：黑底或点穿失败；长按误关/关不掉；探头遮挡主画面或全屏结束不回位；手动设置、照片丢失；自启无法关闭；包内资源失效。P1 可以继续雕琢，但这些门槛不能借“视觉后续优化”跳过。

## 5. Windows / Electron / skinview3d 技术风险与复用命令

| 风险或约束 | 具体处理与验收证据 |
|---|---|
| Electron 启动 | 本机 Windows 11 26200 上 44.9.1 会卡在 `app.whenReady()`；只用已安装的 **44.7.0**。`ELECTRON_RUN_AS_NODE` 必须清空。Agent 不运行可见 GUI；Lead 用用户会话的 scheduled task 或 `docs/SKILLS.md` 已验证的 `cmd start` 脱离启动，并保留现有 live userData。测试用独立 `--user-data-dir`，不要误删/重置现有设置与照片。 |
| CDP 与调试接口 | Lead 在开发构建上用 `--debug-walk --remote-debugging-port=9223`，访问 `http://127.0.0.1:9223/json/list` 选择 `index.html?nikoDebug=1`；使用 `window.__niko.getState()`、`forceWalk()`、`stretch()`、`eat()`、`toggleTorch()`、`getTorch()`、`getParticles()`、`photo()`，并用 `Page.captureScreenshot` 留证。调试入口不得出现在普通打包运行；旧 `window.__nikoViewer` 脚本需更新后才能用。 |
| 透明窗口与全屏 | 保持 `transparent:true`、`backgroundColor:'#00000000'`、`hasShadow:false`、WebGL alpha 0、`setIgnoreMouseEvents(true,{forward:true})`；Raycaster+皮肤 alpha+33 ms 光标轮询的链路要实测底层点击。`focusable:true` + `showInactive()` 不应抢焦点。关闭全屏粒子期间 `pet-window.ts` 的 resize guard 必须跳过；探头也要避免 resize 回灌导致窗口放大循环。全屏识别须区分覆盖整个 `display.bounds` 与普通最大化 `workArea`，排除本应用、桌面、任务栏；失败回正常底部并记日志。 |
| 手势时序 | 250 ms/5 px 拖拽门、默认 1500 ms 火把、2400 ms 聚粒、3000 ms 关闭、约 1200 ms 尾效；长按时移动不误拖，松开取消后续计时。把 `longPressMs` 接入纯状态机，并明确聚粒/关闭是相对火把时长还是固定绝对时长；真实 CDP 鼠标和 100/125/150% DPI 回归优先于只测 timeout。 |
| 模型、动画与资产 | `skinview3d@3.4.2` 对齐 Three 0.156.1；`viewer.zoom=0.55` 是 M0 构图起点。不可改 `public/assets/skin/niko.png`、`public/assets/whale/*.mp3`；MC 资产仅本地使用。新增物品走 IPC 白名单；打包后检查 file URL/asar 加载、纹理最近邻、音频解码、图标尺寸。避免每帧新建几何/纹理；隐藏时暂停无用 rAF 与 WMI 轮询。 |
| 亮度、照片、多屏、自启 | WMI 可能不支持外接屏，不能把 `null` 当 0；冷启动暗处需立即可触发且冷却只在触发后计时。窗口坐标用 DIP、截图按 `scaleFactor` 取物理尺寸；`display_id` 不匹配应报错或显式降级，不能默默存错屏。自启用当前用户登录项，区分安装版/便携版路径；迁移保留既有选择，卸载不删用户数据。 |
| 发布验证 | `package.json` 尚无 `dist`，不得以 `pnpm build` 冒充可运行安装包。测试 portable、NSIS 的独立新配置与旧配置升级；检查 `out/renderer/assets`、日志、照片、单实例、托盘、自启及卸载后的设置/照片。只在本机交付，不上传公共服务。 |

## Questions for the user

以下是**尚未定稿的细节**；用户已决定的 P0、四人分工、方块风、默认自启 ON、交付形式与逐里程碑确认均不重问。可按 `01A、02A…` 批量回复。每题推荐项用于安排设计，用户回答始终优先；每个后续功能点开工前再给该点的选项与预览。

1. **全屏识别的边界：** A（推荐）所有前台独占或无边框覆盖目标屏 ≥98% 的应用触发，普通最大化不触发；B 同样检测独占/无边框，但只对用户选定的应用探头；C 先识别常用全屏应用，设置中可增删名单。选哪项？
2. **仅露头探出的节奏：** A（推荐）每 20–45 s 探 4–8 s；B 每 45–90 s 探 3–5 s；C 每 10–20 s 探 5–8 s。三项均只露头/耳朵。选哪项？
3. **多个显示器同时有全屏窗口时：** A（推荐）只跟随当前前台全屏所在屏；B 固定留在桌宠当前屏；C 按次轮流在有全屏的屏之间探头。选哪项？
4. **托盘单击行为：** A（推荐）只负责找回，已显示时保持显示；B 显示/隐藏切换；C 单击打开菜单。选哪项？
5. **首次向导与既有设置：** A（推荐）新安装一页基础项、可跳过、尺寸实时预览；已有配置不强弹向导，只在设置中提供补填入口；B 新安装三步向导，旧配置首次升级也展示；C 新安装在设置窗口中显示两步向导，旧配置只在托盘提示可重开。选哪项？
6. **登录自启后的出现方式：** A（推荐）安静显示在任务栏上方；B 先驻托盘，单击再出现；C 登录 30 s 后再显示。自启开关仍默认 ON 且可关。选哪项？
7. **声音控制颗粒度：** A（推荐）主音量、总静音、点击音开关和环境/动作音开关；B 每类音效各一个音量滑块；C 只有主音量、总静音。选哪项？
8. **可配置的行为活跃度：** A（推荐）安静/标准/活泼三档，默认安静，并可分别关随机动作；B 单一“动作频率”滑块；C 只有总开关。选哪项？
9. **坐、睡、醒的默认触发：** A（推荐）闲置一段时间先坐，系统空闲 >10 分钟或深夜睡，用户回来先伸懒腰；B 只在系统空闲时睡，活动即醒；C 全部仅手动触发。选哪项？
10. **手动喂食入口：** A（推荐）托盘和自定义快捷键可喂面包，保留 8–20 分钟低频随机吃；B 只从托盘喂，取消随机吃；C 只用自定义快捷键喂，保留低频随机吃。选哪项？
11. **第一个玩具：** A（推荐）Minecraft 雪球，短距离追逐后停下；B 钓鱼竿逗猫，原地伸手；C 小方块球在脚边滚动。选哪项？
12. **摸头反馈：** A（推荐）保留单击歪头/闭眼，补少量爱心与呼噜；连续轻抚触发不同短反应；B 只补爱心/呼噜；C 加多击连招动作。选哪项？
13. **里程碑的实机证据包：** A（推荐）每个功能一张关键 PNG，每个里程碑 1–3 分钟操作录屏，并附日志摘录与缺陷清单；B 每个功能各录 15–30 s 并附截图；C 每个里程碑一段连续回归录屏、关键截图与性能表。选哪项？
14. **开放给用户绑定的动作集合：** A（推荐）拍照、显隐、喂食、玩具、坐/睡/醒、伸展、火把；B 只开放拍照、显隐、喂食；C 所有动作含调试动作都可绑定。选哪项？
15. **快捷键的默认与冲突处理：** A（推荐）保留 `Ctrl+Alt+P` 拍照，其余留空；注册冲突时拒绝并在设置解释；B 给每个动作预设组合键；C 冲突时自动改用相邻组合键。选哪项？
16. **本地源码 zip 的资产范围：** A（推荐）含源码、锁文件、文档和仅供本机使用的必要素材；排除 `node_modules`、`out`、`release`、`artifacts`、用户设置与照片；B 只含源码/清单，素材由本机另存；C 源码与便携/安装产物放同一个 zip。选哪项？

## 6. 首个 48 小时与报告节奏

以下以**用户答复第一批问题后的 T0** 计；等待用户确认不算入执行工时。Lead 可随时重启 live pet，但先备份并保留当前 `userData/settings.json` 与 `Pictures/NikoPet`，验证使用独立配置；不触碰 `%APPDATA%\.minecraft`、`~/.dsh`。

| 时间 | 执行顺序与并行工作 | 产物/闸门 |
|---|---|---|
| T0–4 h | Lead 固定答案、保全未提交检查点、冻结 `FullscreenState`/`ActionId`/设置迁移接口；QA 复核 17 项、build、strict tsc 并采当前状态。 | 基线报告与阻断缺陷单；保留 M1 回滚锚点。 |
| T4–12 h | Platform 做 tray single-click 与 fullscreen watcher/窗口边缘定位；behavior 做只露头姿态/恢复；interaction 检查探头期间手势/关闭冲突；QA 准备 CDP 与四边录屏用例。 | 各 worker 小 diff + 本地验证结果，跨进程通道由 Lead 单独接线。 |
| T12–20 h | Lead 顺序集成，跑 build/test/tsc；在真实桌面测普通最大化、全屏四边、单/多屏、托盘单击、关闭与退出全屏恢复；QA 留短录屏、PNG、日志。 | **G1 首个可见里程碑报告**：完成项、失败项、复现、截图/录屏路径、性能初测与下一步。交给用户确认。 |
| T20–24 h | 等 G1 确认；四 worker 只做下一包接口/素材/测试设计和无需依赖答案的准备。 | 用户确认或提出修正；修正先回 G1，不以沉默视为通过。 |
| T24–36 h（仅 G1 通过后） | Platform 做设置/向导/自启与快捷键注册；behavior 做坐睡醒和动作调度；interaction 做喂食/玩具/摸头入口及长按配置接线；QA 做设置迁移、冷启动暗处、照片和热插拔回归。 | 每个功能点开工前复述选项结论；worker 分别交文件清单、build/test 结果和已知问题。 |
| T36–48 h | Lead 逐个接线，QA 实机回归；platform 预演 builder/资产目录，不提前宣称安装包通过。 | **G2 中期报告**：设置与行为的实机截图/录屏、差异和剩余工时；用户确认后继续 P0-3/P0-4。 |

每个 worker 交付都附：修改文件、关联验收 ID、自动检查退出码、实机需测步骤、回退办法。Lead 每道闸门提供一份可复现报告；Codex 只审 diff、运行证据和截图/录屏是否覆盖验收条件，指出缺口并给通过/退回结论。最终 P0 与 P1 各重跑整套验收并保留本地报告；只有用户确认才进入下一阶段。

**简述：** 以 M1 为回滚锚点，先把 M2/M3 检查点验成可用基线；首个交付聚焦全屏探头与托盘单击。随后并行补设置/自启、行为/互动/快捷键，最后以真实桌面证据验收便携版、安装包和源码 zip。Codex 不承担实现。
